# AGENTS.md — project instructions

This repo was generated by **CopyRoom** from the **template-py** genome
(gh:Bullish-Design/template-py), a RepoMan-managed Python project. This file is
the canonical instructions file — `CLAUDE.md` is a symlink to it, so every agent
tool reads the same source.

## How to work here

- **Run project commands inside the `devenv` shell.** It pins Python and wires RepoMan.
  Never invoke bare `uv`/`python`/`pytest`/`copier`. The host profile puts the `*man`
  commands (copyroom, gitman, docman, repoman) and `testee` on `PATH`. Run `testee` from
  the repository root, in or out of the shell. It starts its own clean devenv shell.
- **The lifecycle is RepoMan's.** Change → verify → integrate. Birth/converge (copyroom)
  and docs (docman) are activities with no fixed order. For the order and the routing,
  start at the `repoman` skill; for domain detail open the per-tool skills.
- **Exit codes are an API:** `0` ok · `1` act on findings · `2` the tool could not run.
- **Verify before you integrate:** run `testee verify --full`. Then use native `jj`:
  `jj describe -m "message"`, `jj new`, `jj bookmark create NAME -r @-`,
  `jj git push --bookmark NAME`, and `gh pr create`. Native `jj git push` runs no hook, so
  run the gate yourself. Never push on red.
- **Gitman only opens workspaces:** `gitman work NAME`. Native `jj` and `gh` do the rest.
- **Testee commands:**
  - `testee verify` — quick profile (ruff, ruff-format). A partial gate.
  - `testee verify --full` — every required check. The full gate.
  - `testee check <id>...` — named checks, such as `ruff` or `pytest`. A partial gate.
  - `testee report` — latest summary. Add `--json` for the saved report.
  - `testee doctor` — inspect the project setup.
- **Testee has no fix command.** Run the formatter directly:
  `devenv shell -- ruff format src tests`. Then rerun `testee verify`.
- **Checks are Nix data** in `devenv.nix` (`testee.checks`). To add or change a check, edit
  that file. Do not add a separate Testee config file or a `[tool.testee]` table.

## Where things live

- `src/` — the Python package; `tests/` — its tests.
- `devenv.nix` / `devenv.yaml` — the reproducible shell, and the Testee checks.
  The Testee module and package pin one tag (`testee_ref`).
- `pyproject.toml` — declares pytest, ruff, ty, and `testee` in the `dev` group at
  the same tag as `devenv.nix`. The host profile puts the managers on `PATH`. There is
  no per-repo `repoman.lock` and no Vendomat closure.
- `.testee/` — run state and reports. Git ignores it. Keep `devenv.lock` tracked.
- `copyroom.project.yml` — advisory project metadata (template id, hooks,
  the `agent:` section).
- `.repoman/project.toml` — the lifecycle manager roster; `.agents/` and `.claude/`
  — machine-local links maintained by the central Devman link plane.

## Agent-files convention

- **Skills** are supplied by the central Devman link plane at
  `.agents/skills/<name>/SKILL.md`; do not commit or materialize a second copy
  in this project.
- **Ownership:** `AGENTS.md` is canonical and `CLAUDE.md` is its symlink. The
  `.agents/` and `.claude/` links are machine-local and stay gitignored.
