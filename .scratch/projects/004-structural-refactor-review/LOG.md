## Adversarial runtime evidence

Executed:

```bash
.venv/bin/python \
  .scratch/projects/004-structural-refactor-review/probes/runtime_adversarial.py
```

Confirmed:

1. A nested list mutation after save makes latest/head state disagree with exact
   and history/log state.
2. Updating an unsaved Delta record writes v1, but exact v1 is not found and
   history cannot validate.
3. Equal state plus one UUID across two streams silently persists only the first
   stream.
4. An interceptor enrichment is persisted but `save()` returns the un-enriched
   value.
5. An interceptor can use unvalidated `model_copy` output to put an invalid type in
   the append-only log.
6. A standard Pydantic `computed_field` is persisted and then rejected during
   hydration.
7. Inline event `created_ts` is `None`; the durable reconstruction has a timestamp.
8. A read inside the current UoW cannot see a preceding write in that UoW.
9. A Store B write nested under Store A's UoW lands in A's database.
10. A datetime update with an outbox subscription fails JSON serialization and
    rolls back.
11. Subscription MRO delivery is derived-to-base despite the base-to-derived
    contract.
12. One function with two matching outbox subscriptions aborts the application
    write on the outbox uniqueness constraint.
13. Rebuilding a valid custom codec's head corrupts its state and leaves an orphan
    head untouched.
14. SQLite filtering `meta.flag=None` matches both explicit JSON null and a missing
    path.
15. A fresh-process CLI drain cannot discover application declarations, exits 0,
    claims it drained one row, and actually retains/backoffs that row.
16. Re-entering the same Store raises `RuntimeError` on outer exit.
